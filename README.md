# 🧠 How I Track a Problem

A problem is marked **completed** only when I can solve it independently.

### Before marking ✅

* [ ] Understand the problem
* [ ] Identify the DSA pattern
* [ ] Think about the brute-force approach
* [ ] Derive an optimized approach
* [ ] Write the code myself
* [ ] Test edge cases
* [ ] Analyze time complexity
* [ ] Analyze space complexity
* [ ] Explain the solution
* [ ] Re-solve without looking at the solution

### Completion Rule

> **Watching a solution ≠ completing a problem.**

If I had to look at the solution, I understand it first and then write the program again myself.

# 🔄 Revision Strategy

Solving a problem once isn't enough.

Problems that are difficult to recall are revisited using the following cycle:

```text
Day 1
  ↓
Solve

Day 3
  ↓
Recall Approach

Day 7
  ↓
Re-solve

Day 14
  ↓
Re-solve Without Help

Day 30
  ↓
Final Revision
```

The focus is on **retaining patterns**, not just increasing the problem count.

# 🌐 Deploy with GitHub Pages

1. Push the repository to GitHub.
2. Open **Settings**.
3. Go to **Pages**.
4. Under **Build and deployment**, select:

   * Source: `Deploy from a branch`
   * Branch: `main`
   * Folder: `/docs`
5. Save.
6. GitHub will generate the live tracker URL.
